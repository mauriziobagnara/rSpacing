# rSpacing 0.10.09

Requires Spacing.Tool2 >= 0.09.10 for the new options. Without them, requests are identical to rSpacing 0.10.08. Tool2 0.09.09 or earlier ignores the new fields, and rejects a repeated crop.

- **Repeated crops:** `new_spacing_scenario()` now accepts the same crop more than once (e.g. Wheat, Oats, Maize, Wheat); each `spacing_crop()` keeps its own management.
- **Sowing:**
  - `spacing_crop(sowing_date = )` sets a fixed sowing day; `sowing_window` can then be `NULL`.
  - `spacing_crop(sowing_rule = spacing_sowing_rule())` sets conditions on extractable soil water, recent rain and soil temperature, optionally forcing sowing at the end of the window.
- **Irrigation:** `spacing_crop(irrigation_schedule = )` takes a list of `spacing_irrigation_event()`, triggered by date, days after sowing, stage, sowing day or days after the previous harvest.
- **Fertilisation:** `spacing_fertiliser_application(trigger = "DaysAfterPreviousHarvest")` applies fertiliser before sowing.
- **Residues and crop types:**
  - `spacing_residue_removal()`: removal or burning of the surface residue after harvest.
  - `spacing_termination()`: cover crops, ended without harvest.
  - `spacing_intercrop()`: crops sown together with the main crop.
  - `spacing_perennial()`: crops kept for several years with an annual harvest.
- **Outputs:** new `spacing_report_spec()`, passed through `new_spacing_scenario(report = )`, adds harvest or daily variables, drops default daily variables, or changes the daily report event.
- New example `inst/examples/scenario_rotation_options.R`; new tests `test-rotation-options.R`, plus an integration test with a real Tool2 0.09.10 run.

**Revision of 25 November 2026**

- **Cultivars:** `spacing_cultivars()` returns the full APSIM cultivar catalogue (573 cultivars, 22 crops), with a `standard` column for the standard rotation (Claire, B_130, Generic_MG1).
- **Documentation:** every function is fully documented, with runnable examples; all help pages are generated by roxygen2.
- **Fixes:**
  - `new_spacing_scenario()` accepts a named list of crops; a named list used to be written as a JSON object that Tool2 rejected.
  - `spacing_coordinates()`, `plot_spacing_map()` and `plot_spacing_location()` accept scenarios and the runs and results of scenarios.
  - `read_spacing_run_spec()` returns layered soil values as numeric vectors; before, they were lists.
  - `plot_spacing_yield()` and `plot_spacing_comparison()` take the year from the harvest date when there is no `Year` column. `plot_spacing_comparison()` labels scenarios with the list names or the scenario identifier, instead of the run identifier.
  - Report plots (`plot_spacing_report()`, `plot_spacing_report_panel()`) show a crop variable only for the harvests of that crop. Before, the other crops' harvests appeared as zeros.
  - ggplot2 4.x compatibility: the specialised plots no longer overwrite the plot's `data` (in ggplot2 4.x that broke, for example, `plot_spacing_soil_carbon(type = "change")` with "object 'value' not found"). The table used for a plot is now read with the new `spacing_plot_data()`.
  - Tests compare file paths after `normalizePath()`, so Windows short (8.3) temporary paths no longer fail them.
- **Workflows shipped in `inst/rmarkdown/`:** cookbook v1.00, scenario comparison v1.00, five-year v1.08, Morris v1.18 and uncertainty v1.06 replace five-year v1.05, Morris v1.14 and uncertainty v1.04. The README of that folder is updated and now uses the correct `system.file("rmarkdown", package = "rSpacing")`.
- **Documentation clean-up:** new package README; the examples and the vignette use the standard rotation cultivars (Claire, B_130, Generic_MG1); the operational manual is revision 10 for 0.10.09 (`rSpacing_v0.10.09_complete_operational_workflow_rev10_model_run_EN.Rmd`); the Italian five-year demo script `inst/examples/rSpacing_APSIMx_5year_three_crops_tables_plots.R` (superseded by the five-year workflow) is removed.
- **English labels:** the variable dictionary (titles, descriptions and units) and all plot titles and axis labels are now in English. They were in Italian.

# rSpacing 0.10.08

Requires Spacing.Tool2 >= 0.09.09 for the new management events. Requests built without them are identical to rSpacing 0.10.07 and run on Tool2 0.09.07/0.09.08. Tool2 0.09.08 or earlier silently ignores the new fields.

- **Fertilisation:**
  - `spacing_fertiliser_application()` gains `trigger = "Date"` (`date`, `d-mmm`), `trigger = "Stage"` (`stage`, an APSIM stage name) and `depth_mm`. Any APSIM fertiliser type containing N is accepted (`spacing_fertiliser_types()`).
  - Doses stay in kg N/ha: Tool2 converts them to product using the N fraction.
  - `spacing_fertilisation()` gains `fertiliser` and `depth_mm` for the sowing dose. Stage names are checked against the crop in `spacing_crop()` (`spacing_crop_stages()`).
- **Organic inputs:**
  - `spacing_organic_n()` accepts any APSIM residue type (`spacing_residue_types()`, with carbon fractions).
  - New `spacing_organic_application()` for inputs with their own trigger: `Sowing`, `DaysAfterSowing`, `Date` or `DaysAfterPreviousHarvest`. Pass them through `spacing_crop(organic_applications = )`.
- **Tillage:** new `spacing_tillage_operation()` with the same triggers, e.g. autumn ploughing before a spring crop. Pass them through `spacing_crop(tillage_operations = )`, which replaces the sowing-day `tillage`; `list()` means no tillage.
- **Initial residue:** new `spacing_surface_residue()`, passed through `new_spacing_scenario(surface_residue = )`.
- **Plots:** the specialised fertilisation plot prefers the new Tool2 daily column `FertMineralN_kgNha` (mineral N actually applied) over `FertN_kgNha` (product amount).
- **APSIM tables:** fertiliser types, residue types and stage names are stored in `inst/extdata/apsim`. They were exported from the APSIM Models.dll of Tool2 0.09.09. Tool2 repeats every check against the APSIM version it runs.
- New example: `inst/examples/scenario_management_events.R`. New tests: `test-management-events.R`, plus an integration test with a real Tool2 0.09.09 run.

# rSpacing 0.10.07

Requires Spacing.Tool2 >= 0.09.07 for the new scenario API; 0.09.08 is recommended (crop-failure handling, exit codes). Version 0.10.06 is reserved for the experimental branch.

- **Complete scenarios sent with `--request`.** New functions:
  - `spacing_crop()`, `spacing_tillage()`, `spacing_organic_n()`;
  - `spacing_soil_profile()`, `as_spacing_soil_profile()`;
  - `new_spacing_scenario()`, `as_spacing_tool2_request()`, `write_spacing_scenario()`.

  Together they describe rotation order, cycles, cultivars, sowing, basal and split N, automatic irrigation, tillage, organic N, every soil parameter (including crop LL/KL/XF and WaterBalance parameters), weather and period. No C# recompilation is needed.
- **`run_spacing()` accepts a `spacing_scenario`.** It writes `request.json` in the run directory and passes `--request`, then returns Tool2's `result.json` in `run$result`.
  - It raises `spacing_process_error` when the APSIM simulation fails, even though Tool2 exits with status 0.
  - It warns when a crop was ended by the rotation safety without reaching maturity.
- **`build_spacing_args()`** gains `request_file` for scenarios.
- **`spacing_config(use_compiled = TRUE, executable = "<...>/spacing-tool2.dll")`** runs the framework-dependent build as `dotnet <dll>`. This needs only the .NET runtime, not the SDK or a NuGet restore.
- **Validation in R.** The checks applied by Tool2 0.09.07 are repeated in R, so invalid inputs fail before the model runs:
  - `AirDry <= LL15 <= DUL < SAT`, `SAT <= 1 - BD/2.65`, SW and crop LL bounds;
  - optional soil columns all-or-none;
  - one occurrence per crop in a rotation;
  - three tillage types, `manure` organic inputs.
- `new_spacing_scenario()` gains `max_crop_days` and `stall_days`, sent to Tool2 as `rotation_safety` (used from Tool2 0.09.08).
- `run_spacing()` interprets the Tool2 0.09.08 exit codes:
  - 2 = APSIM simulation failed;
  - 3 = invalid request or unexpected error.

  The error message includes Tool2's `ERRORE:` line. The forced-end warning names the reason (`failed`, `stalled`, `max_days`).
- New example: `inst/examples/scenario_tool2_request.R`.
- The existing `new_spacing_request()` rotation-string API is unchanged.
