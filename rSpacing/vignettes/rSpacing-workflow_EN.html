1 About this manual

This vignette is the main entry point for a new rSpacing user. It explains the complete workflow from request construction to model execution, result inspection, plotting, soil and management diagnostics, and preparation of advanced analyses. The emphasis is not only on function syntax, but also on what each returned object means, which checks should be performed, and which conclusions are supported by the available APSIMx output.

The package has two distinct operating modes:

  1. Result-reading and analysis mode. A previously imported spacing_result is inspected without requiring .NET, APSIMx, or the C# source tree. This is the mode used while the vignette is built.
  2. Model-execution mode. rSpacing constructs a request, calls the external Spacing.Tool2 runtime, captures logs and provenance, and imports the generated APSIMx outputs. This mode requires a compatible C# solution and .NET runtime.

A new user should first work through the vignette with the supplied fixture, then configure the external runtime and execute a small mock-weather run, and only afterwards start long rotations, Morris analyses, or uncertainty ensembles.

2 Reproducible example used by the manual

This vignette uses a single real model run that has already been imported as a spacing_result:

The run was produced with Spacing.Tool2 v0.09.05 and mock = TRUE weather data. APSIMx is not rerun while the vignette is built. All subsequent tables and plots are derived from the real fixture.

The fixture represents a Maize example and is designed for documentation and regression checking. mock = TRUE means that the meteorological input is generated by the workflow rather than retrieved from an external service. The fixture demonstrates package behaviour, but it is not a site-calibrated agronomic experiment.

4 Request and execution

4.0.1 Building and validating a request

A request describes what should be simulated. The example specifies coordinates, crop, mock-weather mode, and a scenario identifier. validate_spacing_request() checks the R object before any external process starts, so malformed inputs can be corrected without creating partial APSIMx runs.

How to read the printed request. Confirm coordinates, rotation or crop, years when supplied, scenario identifier, output destinations, and the mock flag. Validation confirms structure and admissible values; it does not prove that the external runtime is installed or that APSIMx will complete.

request <- new_spacing_request(
  latitude = 44.9,
  longitude = 10.63,
  rotation = "Maize",
  mock = TRUE,
  scenario_id = "reference_maize"
)
validate_spacing_request(request)
print(request)

4.0.2 Executing the external model

The code is intentionally shown but not evaluated during vignette construction. spacing_config() identifies the local Spacing.Tool2 environment; validate_spacing_config(..., check_dotnet = TRUE) verifies required paths and the .NET command; run_spacing() executes the request and captures status, standard output, standard error, and generated files; read_spacing() imports the completed run into a spacing_result.

The example reads the root from RSPACING_SPACING_ROOT instead of embedding a personal path. For the current two-repository workflow, this variable should point to the sibling apsim directory containing src/Spacing.Tool2. Always inspect the run status and logs before analysing outputs. error_on_status = TRUE is appropriate for interactive testing because a non-zero external status stops immediately.

spacing_root <- Sys.getenv("RSPACING_SPACING_ROOT")
if (!nzchar(spacing_root)) {
  stop(
    "Set RSPACING_SPACING_ROOT to the local directory containing ",
    "the Spacing.Tool2 solution before running the model."
  )
}

cfg <- spacing_config(spacing_root)
validate_spacing_config(cfg, check_dotnet = TRUE)
run <- run_spacing(cfg, request, error_on_status = TRUE, echo = TRUE)
result <- read_spacing(run)

5.0.2 Accessing daily, report, crop-summary, and unit tables

Dedicated accessors provide stable interfaces to common outputs. The daily table is required here, so strict extraction is used. Report and crop-summary tables are optional because their availability depends on the APSIMx reporting configuration. spacing_units() provides the evidence needed to interpret column scales.

Only the first 20 rows are displayed. The preview is for orientation, not for calculating totals or final values. For cumulative fluxes use the complete daily table; for end-of-cycle summaries prefer the appropriate report or crop-specific column and verify units before comparison.

daily <- spacing_daily(result, strict = TRUE, allow_empty = FALSE)
report <- spacing_report(result, strict = FALSE, allow_empty = TRUE)
crop_summary <- spacing_crop_summary(result, strict = FALSE, allow_empty = TRUE)
units <- spacing_units(result)

9.0.1 Distinguishing irrigation requested from irrigation applied

The chunk searches the imported daily output for a numeric irrigation variable. When found, it constructs daily amounts and their cumulative sum. The figure therefore represents water exported by APSIMx as applied irrigation, not merely the irrigation rule sent in the request.

Read the daily line to identify event timing and magnitude, and the cumulative line to read total applied depth. Missing output means that the current report does not expose applied irrigation; it does not automatically mean that irrigation was disabled. Confirm the exact source column and unit before quoting totals.

12 Carbon by soil layer

12.0.1 Reading carbon by soil layer

The code searches layered variables whose names contain Soil C or carbon while excluding CO2 fluxes. If a compatible variable exists, plot_spacing_soil_profile(..., type = "profile") displays its vertical distribution. Errors are trapped so that one unsupported variable does not prevent the entire manual from compiling.

A profile represents the selected variable across layers at the time or aggregation used by the plotting method. Compare profiles only when variable, unit, layer definition, and date are equivalent. The absence of a layered carbon output does not invalidate the total Soil C stock; it only limits vertical interpretation.

soil_carbon_variables <- soil_variables[
  grepl("soilc|carbon", soil_variables, ignore.case = TRUE) &
    !grepl("co2", soil_variables, ignore.case = TRUE)

if (length(soil_carbon_variables)) {

An empty crop_summary table is not sufficient to conclude that APSIMx produced no grain. The vignette checks all imported tables and displays columns associated with yield, grain, or harvest.

13.0.1 Why yield is searched across all imported tables

A crop-summary table can be empty even when another APSIMx report contains grain or harvest information. This chunk therefore flattens available CSV and DataStore tables and inventories every column whose name suggests yield, grain, or harvest. For numeric columns it records the number of positive values and the maximum.

This is an evidence-discovery step. A matching name does not guarantee that the column is harvested yield, and a maximum is not automatically the final crop yield. Use table name, column definition, unit, crop identity, and event date to select the authoritative response.

all_tables <- c(
  flatten_tables(result$csv, "csv"),
  flatten_tables(result$datastore, "datastore")
)

yield_candidates <- do.call(rbind, lapply(names(all_tables), function(table_name) {
  data <- all_tables[[table_name]]
  columns <- grep(
    "yield|grain|harvest",
    names(data),
    value = TRUE,
    ignore.case = TRUE
  )
  if (!length(columns)) return(NULL)

  do.call(rbind, lapply(columns, function(column) {
    value <- data[[column]]
    data.frame(
      table = table_name,
      column = column,
      class = paste(class(value), collapse = "/"),
      positive_n = if (is.numeric(value)) sum(value > 0, na.rm = TRUE) else NA_integer_,
      maximum = if (is.numeric(value) && any(is.finite(value))) {
        max(value, na.rm = TRUE)
      } else {
        NA_real_
      },
      stringsAsFactors = FALSE
    )
  }))
}))

if (is.null(yield_candidates)) {
  yield_candidates <- data.frame(
    table = character(), column = character(), class = character(),
    positive_n = integer(), maximum = numeric()
  )
}

15.0.2 Defining parameters for sensitivity or calibration

The catalogue associates a readable parameter ID with crop, scope, exact APSIMx path, type, unit, admissible bounds, transformation, and application stage. validate_spacing_parameters() checks proposed values against this contract before a model run.

Bounds define the analysis domain, not biological confidence intervals. The APSIMx path must be confirmed against the model and cultivar actually used. For large Morris or calibration experiments, perform an isolated preflight for every parameter before constructing the full design.

  crop = "Maize",
  scope = "cultivar",
  apsim_path = "Leaf.Photosynthesis.RUE.FixedValue",
  type = "double",
  unit = "g/MJ",
  lower_bound = 1.2,
  upper_bound = 3.2,
  transform = "identity",

16 Recommended workflow for a new user

  1. Install rSpacing with the vignette and open this manual.
  2. Inspect the supplied fixture with inventory_spacing_result() and the dedicated table accessors.
  3. Identify variables by exact name and unit before plotting or aggregating them.
  4. Configure the external Spacing.Tool2 runtime and verify .NET with a small mock = TRUE request.
  5. Inspect status, standard output, standard error, generated files, and the imported spacing_result.
  6. Reproduce the single Maize example before creating a multi-year rotation.
  7. Validate soil, management, request, and parameter objects before launching simulations.
  8. Use preflight runs before Morris, uncertainty, calibration, or large batches.
  9. Keep run folders separate from persistent results and record package, C# runtime, request, and commit versions.

17 Troubleshooting checklist

  • The vignette is not listed after installation. Install with build_vignettes = TRUE or install a source tarball built with vignettes.
  • The fixture cannot be found. Confirm that inst/extdata/reference_maize/result.rds is present in the source package and extdata/reference_maize/result.rds is present after installation.
  • dotnet is not found. Run Sys.which("dotnet") and system2("dotnet", "--info"); install or configure .NET 8 before model execution.
  • The C# runtime is not found. Set RSPACING_SPACING_ROOT to the local apsim repository containing src/Spacing.Tool2.
  • The model run fails. Inspect the run status, stdout, stderr, request JSON, configuration JSON, and manifest before changing R code.
  • A table is empty. Check the complete result inventory and DataStore tables. An empty crop summary does not prove that no crop output exists.
  • A plot is empty or fails. Verify variable name, numeric type, non-missing values, unit, and temporal or layered structure.
  • Management cannot be verified. Distinguish the requested management object from APSIMx output evidence of applied events.
  • Yield or biomass values are duplicated across crops. Require exact crop-specific columns rather than selecting the first name matching a general pattern.

18 Scope and limitations

The bundled fixture is a reproducible demonstration of the rSpacing interface. It uses mock weather and a predefined model configuration. The manual teaches how to inspect evidence and construct reproducible workflows; it does not establish that the simulated agronomic or environmental values are calibrated for a particular site. Scientific interpretation requires appropriate observed data, defensible input distributions, validated management transfer, model-version control, and explicit documentation of units and aggregation rules.
